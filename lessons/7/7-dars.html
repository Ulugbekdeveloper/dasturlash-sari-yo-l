2-qism

Git

Terminal, uch joy va birinchi commit.

Git asosan terminalda ishlatiladi — 5-bobda Engelbart aytib bergan buyruq qatorida. Uni ochishning eng qulay yo'li — VS Code'ning ichida:

  • VS Code'da frontend papkangizni oching.
  • Yuqori menyudan Terminal → New Terminal ni tanlang (yoki ctrl + `). Pastda qora oyna ochiladi.
  • Windows'da terminal turi sifatida Git Bash ni tanlang — u Git bilan birga o'rnatiladi va Mac'dagi buyruqlarni tushunadi.

Uchta buyruqni yozib ko'ring. 6-bobdagi Unix terminalidan ularni taniysiz:

pwd        # hozir qaysi papkadaman?
ls         # bu papkada nima bor?
cd ..      # bir papka yuqoriga chiqish
cd frontend  # frontend papkasiga kirish
Ustoz maslahatiTerminaldan qo'rqmang. U siz yozgan buyruqni bajaradi, xolos. Buyruqni oxirigacha yozish shart emas: bir necha harf yozib tab tugmasini bossangiz, terminal fayl yoki papka nomini o'zi to'ldiradi. Oldingi buyruqni qaytarish uchun — yuqori strelka.

Avval Git kompyuteringizda bormi, tekshiring:

git --version
  • Mac: agar git version 2.x chiqsa — tayyor. Chiqmasa, Mac o'zi "Command Line Tools'ni o'rnatasizmi?" deb so'raydi — rozi bo'ling.
  • Windows: git-scm.com saytidan yuklab o'rnating. O'rnatishda hamma savollarga standart javobni qoldirsangiz bo'ladi.

Keyin Git'ga o'zingizni tanishtiring. Har bir commit'ga shu ism va email yoziladi — kim nimani o'zgartirganini bilish uchun:

git config --global user.name "Ali Valiyev"
git config --global user.email "ali@mail.uz"

Bu buyruqlarni faqat bir marta yozasiz. --global — "shu kompyuterdagi barcha loyihalar uchun" degani. Emailni keyinroq GitHub'da ochadigan akkauntingiz bilan bir xil qiling.

Nega o'rtada tayyorlov maydoni bor? Tasavvur qiling, siz bir vaqtda ikki ish qildingiz: sarlavha rangini o'zgartirdingiz va formaga yangi maydon qo'shdingiz. Ularni ikki alohida commit qilish yaxshiroq — keyin har birini alohida topish va kerak bo'lsa bekor qilish oson. git add bilan nimani "suratga" kiritishni o'zingiz tanlaysiz.

Pochta misoliIshchi papka — stolingizdagi narsalar. Tayyorlov maydoni — yuborishga tayyorlanayotgan quti: unga faqat kerakli narsalarni solasiz. Commit — qutini yopib, ustiga "nima bor va nima uchun" deb yozib, javonga qo'yish.

Terminalda frontend papkangizda turib, ketma-ket yozing:

git init                          # bu papkada Git'ni yoqish (bir marta)
git status                        # qaysi fayllar o'zgardi?
git add .                         # hamma o'zgarishlarni tayyorlov maydoniga
git commit -m "Birinchi versiya"  # surat olish
git log --oneline                 # tarixni ko'rish
  • git init papkaning ichida yashirin .git papkasini yaratadi. Butun tarix shu yerda saqlanadi. Uni qo'lda o'chirmang!
  • git add . — nuqta "hamma narsa" degani. Bitta faylni qo'shish uchun: git add index.html.
  • -m — "message", izoh. Qo'shtirnoq ichida nima qilganingizni yozasiz.

Keyin index.html da biror narsani o'zgartiring va yana git status yozing. Git o'zgargan faylni darhol ko'radi. Qaytadan add va commit — va tarixda ikkinchi surat paydo bo'ladi.

Git tarixi · Linus hikoya qiladiMen Git'ni 2005-yil aprelda yozdim. Linux yadrosi ustida dunyo bo'ylab minglab odam ishlardi va biz bir necha yil BitKeeper degan pullik dasturdan bepul foydalanib kelgandik. Bu ruxsat bekor qilinganda, menga yoqadigan boshqa dastur topilmadi. Shunda o'zim yozdim. Taxminan o'n kundan keyin Git o'zining kodini o'zida saqlay boshladi, bir necha haftadan keyin esa Linux kodi ham unga ko'chdi. Nomi haqida hazil qilib aytganman: "git" — inglizcha so'kish so'zi, taxminan "ahmoq" degani. Men barcha loyihalarimni o'zimga o'xshatib nomlayman: avval Linux, endi Git.

.gitignore — Git e'tibor bermasligi kerak bo'lgan fayllar ro'yxati. Masalan, Mac har bir papkaga yashirin .DS_Store faylini qo'yadi, u loyihaga kerak emas. Papkangizda .gitignore nomli fayl yarating va ichiga yozing:

git diff — commit qilishdan oldin aynan nima o'zgarganini ko'rsatadi: o'chirilgan qatorlar qizil (-), qo'shilganlar yashil (+).

git diff
-  <h1>Salom</h1>
+  <h1>Salom, dunyo!</h1>
Ustoz maslahatiVS Code'ning chap panelidagi Source Control belgisi (uch nuqta va chiziqlar) — Git uchun tugmali oyna. Unda o'zgargan fayllar, diff va "Commit" tugmasi bor. Terminalni tushunib olgach, ikkalasidan qaysi biri qulay bo'lsa, shuni ishlating.

3-qism

GitHub va Vercel

Kodingizni bulutga qo'yamiz va saytni internetga chiqaramiz.

Git — kompyuteringizdagi dastur. GitHub — Git repozitoriylari saqlanadigan sayt. U kodingizning internetdagi zaxira nusxasi, birga ishlash joyi va dasturchining ochiq portfoliosi.

  • github.com da bepul akkaunt oching. Foydalanuvchi nomini jiddiy tanlang — u rezyumengizda turadi.
  • New repository tugmasini bosing, nom bering (masalan, mening-sahifam), Public ni qoldiring va Create ni bosing.

Eng oson yo'l — VS Code orqali. Source Control panelida Publish to GitHub tugmasi bor. Uni bossangiz, VS Code GitHub'ga kirishni so'raydi, repozitoriy yaratadi va kodingizni yuklaydi. Parolni siz brauzerda, GitHub'ning o'z sahifasida kiritasiz.

Terminal orqali — GitHub repozitoriy sahifasida ko'rsatadigan buyruqlar:

git remote add origin https://github.com/ali/mening-sahifam.git
git branch -M main
git push -u origin main
  • remote — "uzoqdagi" nusxa. origin — unga beriladigan odatiy nom.
  • main — asosiy tarmoq (branch) nomi. Tarmoqlar haqida keyinroq gaplashamiz.
  • push — commitlaringizni GitHub'ga "itarish". Keyingi safar shunchaki git push yetarli.
  • git pull — teskarisi: GitHub'dagi yangi o'zgarishlarni kompyuteringizga tortib olish.
XavfsizlikRepozitoriy ochiq — uni hamma ko'radi. Unga hech qachon parol, karta raqami yoki maxfiy kalit yozilgan fayl qo'ymang. GitHub'ga kirishda ikki bosqichli himoyani (2FA) yoqing.

GitHub repozitoriyni ochgan odamga birinchi bo'lib README.md faylini ko'rsatadi. U Markdown tilida yoziladi — HTML'ning juda soddalashtirilgan ko'rinishi:

README.md
# Mening sahifam

Frontend o'rganish yo'lidagi
**birinchi** saytim.

## Nimalar bor
- Bosh sahifa
- Bog'lanish formasi

[Saytni ochish](https://mening-sahifam.vercel.app)
HTML'da xuddi shu
<h1>Mening sahifam</h1>
<p>... <strong>birinchi</strong> ...</p>
<h2>Nimalar bor</h2>
<ul>
  <li>Bosh sahifa</li>
  <li>Bog'lanish formasi</li>
</ul>
<a href="...">Saytni ochish</a>
  • # — sarlavha (h1), ## — kichikroq (h2).
  • **so'z** — qalin, - — ro'yxat bandi.
  • [matn](manzil) — havola.

Markdown juda keng tarqalgan: GitHub, Telegram, ko'p eslatma ilovalari va hatto suhbat sun'iy intellektlari ham uni tushunadi.

GitHub kodni saqlaydi. Uni hamma ochadigan saytga aylantirish uchun hosting kerak — sahifalaringizni kecha-kunduz tarqatib turadigan server. 2-darsdagi brauzer → server sayohatini eslang: endi o'sha serverni o'zingiz ulaysiz.

  • vercel.com ga kiring va Continue with GitHub ni tanlang.
  • Add New → Project ni bosing va ro'yxatdan mening-sahifam repozitoriysini tanlang.
  • Sozlamalarga tegmang — oddiy HTML/CSS sayt uchun hammasi tayyor. Deploy ni bosing.
  • Bir necha soniyadan keyin sizga manzil beriladi: mening-sahifam.vercel.app. Uni telefoningizda oching!

Eng yoqimli joyi: bundan keyin har safar git push qilganingizda Vercel buni ko'radi va saytni o'zi yangilaydi. Kod yozasiz → commit → push → bir daqiqada yangi versiya internetda.

VS Code→git commit→git push→GitHub→Vercel→sayt.vercel.app

Vercel o'rniga GitHub Pages yoki Netlify ham bepul va xuddi shunday ishlaydi. Muhimi — bitta tanlab, odat qilish.

Git tarixi · Linus hikoya qiladiMen Git'ni Linux uchun yozgandim, ommaviy bo'lishini kutmagandim. 2008-yilda bir guruh dasturchilar Git ustiga GitHub saytini qurishdi va hammasi o'zgardi: kod saqlash, birga ishlash va boshqalarning loyihasiga yordam berish bir necha bosishga aylandi. 2018-yilda Microsoft GitHub'ni 7,5 milliard dollarga sotib oldi. Bugun GitHub'da yuz milliondan ortiq dasturchi bor.

Git nima?

Git tarixni saqlaydi. Sayt yaratish — HTML/CSS, internetga chiqarish — hosting.

git add nima qiladi?

add — tayyorlash, commit — surat olish, push — yuborish.

Git va GitHub farqi nima?

Git'ni GitHub'siz ham ishlatish mumkin. GitHub uning ustiga qurilgan xizmat.

Qaysi commit xabari yaxshiroq?

Nima va nima uchun — bir gapda.

push — itarish (yuborish), pull — tortish (olish).

Ochiq qurish

Endi sizda haqiqiy havola bor. Uni ishlatish vaqti keldi.

Ko'p muvaffaqiyatli asoschilar mahsulotini yashirin qurmaydi — ochiq quradi (build in public). Har hafta qisqa xabar yozishadi: nima qildim, nima o'rgandim, keyingi qadam nima. Bunda uch narsa yutasiz:

  • Mas'uliyat. Hamma kutayotganini bilsangiz, ishni tashlab qo'yish qiyinroq.
  • Erta fikr. Odamlar g'oyangizni mahsulot tayyor bo'lishidan oldin baholaydi.
  • Birinchi foydalanuvchilar. Sizni kuzatganlar mahsulot chiqqanda birinchi bo'lib sinab ko'radi.
GitHub — jonli rezyumeProfilingizdagi yashil kvadratchalar — har kuni qilgan commitlaringiz. Ish beruvchi rezyumedagi "tirishqoqman" degan so'zdan ko'ra, bir yillik yashil to'rga ko'proq ishonadi. Kichik bo'lsa ham, har kuni commit qiling.
